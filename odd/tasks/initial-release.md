### Proposed engineering defaults adopted for the initial implementation

These were presented before implementation was requested; keep them explicit rather than attributing them to individual user answers.

- **D1 — Stack.** Python platform, Docker isolation, SQLite metadata and local artifacts. Prefer standard-library dependencies when sufficient; use deterministic tests. Choose concrete adapters only after checking primary documentation.
- **D2 — Scores.** A passing unit test earns its assigned score; nonpassing tests earn zero. Report earned/max score, normalized score, raw pass percentage, per-test outcomes, and averages over eligible trials. Evaluator infrastructure faults are not silently converted to a zero agent score.
- **D3 — Accounting.** Unknown usage/cost remains unknown, never zero; mark incomplete accounting. Report cache/reasoning details when supplied. Do not double-count streamed usage events or parent/child rollups. Stop limits are best-effort at observable boundaries; explain in-flight cost overshoot.
- **D4 — Configuration.** Validate manifests and relative paths before side effects. Resolve paths relative to the manifest. Explicit overrides take precedence over selected inherited configuration; reject unsupported or unsafe combinations with an actionable error. Secrets are explicit environment references, never exported to artifacts or API responses.
- **D5 — Runtime.** Separate setup, agent-active, human-wait, and evaluation durations. Keep aggregate wall time distinct from cumulative agent duration. Use configurable concurrency; no silent request or whole-run retries. Retain infrastructure-affected runs separately from agent rankings.
- **D6 — Read-only dashboard.** Bind locally by default; expose sanitized live run summaries and results, no run mutations or secret-bearing data. Plain JSON and a small HTML interface are sufficient for the first release.
